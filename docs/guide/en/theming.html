Theming

Colours as CSS variables

A theme on an HTML screen is what it is on the web: custom properties, a prefers-color-scheme media query, and a class when the user overrides the system. Nothing in this crate replaces that, so a stylesheet written for a browser keeps its themes.

Custom properties

samples/theme writes every colour as a var(). A light set is the default, a dark set applies under prefers-color-scheme: dark, and a class on the app's root wins over both.

Light and dark

HtmlConfig::color_scheme answers prefers-color-scheme. It is ColorScheme::Light unless you say otherwise. While the app runs, the theme decides: when a handler calls use_theme().set_color_scheme(ColorScheme::Dark) (or Light), the page is restyled in the same frame and only the boxes whose style changed are sent. A theme that follows the system leaves the configured scheme in place.

With no class on the app, Dark picks the dark set. The test checks every colour on the page against both sets.

Overriding the system

The toggle button puts light or dark on the root element. That is a class change and nothing else, so only colours change.

The test clicks the toggle and checks the layout diff: entries changed, none were added or removed, the order is the same, and every changed entry differs from before in its colours only.

Not yet

  • Following the system while running. planned The renderer learns of a system change first and applies it on its own side; compose-rust has no event that tells the Host, so an HTML screen whose theme follows the system keeps its configured scheme. A theme switched to light or dark by the application is followed (see above) (#43).
  • CSS variables as colour roles. planned On a screen that mixes HTML and widgets, both will follow one theme, with the CSS variables tied to the widgets' colour roles. The plan already has the seam for it: a ColourResolver may replace a computed colour with the role it stands for, so a theme change will not need a new layout. See Mixing the two.
  • Animated theme changes. planned A transition: background-color does not play today (#46).
