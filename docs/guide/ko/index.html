Rust로 쓰는 선언형 UI,그리는 일은 Compose가.

컴포넌트는 rsx!와 훅, 시그널로 작성합니다. AOT 컴파일된 Compose Multiplatform 렌더러가 그것을 그립니다. Compose의 텍스트 레이아웃과 위젯, 플랫폼 IME를 그대로 씁니다.

웹뷰도 동봉된 JVM도 없는 Rust 네이티브 데스크톱 UI입니다.

시작하기 가이드 읽기 GitHub 
rsx! {
    Column {
        fill_max_width: true,
        Text { text: "대화" }
        TextField {
            placeholder: "메시지를 입력하세요",
            on_key_down: move |e| {
                // Enter는 제출, Shift+Enter는 줄바꿈
                if e.key() == Key::Enter && !e.shift_key() {
                    submit();
                    e.consume();
                }
            },
        }
    }
}

UI는 한 언어로, 픽셀은 한 엔진으로

컴포넌트와 상태는 Rust가 갖습니다. 픽셀과 텍스트 스택, 입력기는 Kotlin이 갖습니다. 그 사이에는 좁은 C ABI가 있습니다. 동기 호출이고, 같은 스레드에서 돌며, 복사가 없습니다. 그래서 키 하나를 눌렀을 때 같은 프레임 안에서 답이 돌아옵니다.

직렬화하지 않습니다. 비동기 브리지도, 웹뷰도, 배포 바이너리 안의 JVM도 없습니다.

61.6 MB창을 띄운 상태의 메모리, M1에서 측정
12.5 µs클릭에서 diff, 인코딩까지 p99
0경계에서 프레임당 힙 할당
JVM 없음Java가 없는 머신에서 그대로 실행

Mac mini(M1, 16GiB, macOS 26.5.1) 릴리스 빌드에서 측정했습니다. 측정 방법은 아키텍처 문서에 있습니다.

현재 상태

플랫폼상태
macOS 데스크톱한글 IME 입력까지 포함해 전 구간 동작
Windows, Linux 데스크톱Rust 쪽은 이식 가능. 렌더러 빌드 스크립트는 아직 없음
iOS, Android설계 완료, 구현 전
Web경계 방식은 실측으로 확정, 구현 전

초기 단계 프로젝트이고, 그 사실을 감추지 않습니다. 명세에 확정된 것과 초안인 것, 아직 검증되지 않은 것을 구분해 적어 두었습니다.

시작하기

툴체인 설치, 렌더러 빌드, 데모 실행까지.

UI 작성

위젯과 Modifier, 이벤트, 그리고 IME 조합을 지키는 텍스트 필드 규칙.

디자인 시스템

Material 3, Apple HIG, Fluent. 하나로 통일하거나 플랫폼을 따라가거나.
